# v0.36.0 Public API Review

Date: 2026-07-27

Scope: provider-neutral request and response header types, Hetzner prepared
headers, reqwest forwarding and capture, testkit matching, and diagnostics.

## Implementation Decision

The v0.36 implementation is ready for exact-commit security review with these
boundaries:

- request names and values are borrowed, allocation-free, `no_std`, and
  individually bounded;
- request blocks preserve order and preflight count plus aggregate encoded
  size;
- response blocks own a fixed-capacity byte arena and descriptor table;
- all header names are unique under ASCII case-insensitive comparison;
- all header values are redacted from `Debug`;
- sensitivity is explicit on requests, preserved from adapters, and defaults
  to sensitive for unknown response fields;
- only reviewed content, length, date, and rate-limit response metadata is
  classified as public;
- secret-capable header values, collections, responses, and wrappers do not
  expose ordinary equality;
- typed `Accept` and `Content-Type` constructors reuse validated media types;
- HTTP/1 field-line encoding does not modify undersized output.

## Ownership Policy

Safe caller APIs cannot construct request headers for `Host`,
`Content-Length`, `Transfer-Encoding`, `Authorization`, proxy authentication,
or hop-by-hop connection fields. Content length and transfer framing remain
HTTP implementation responsibilities. Bearer authorization remains adapter
credential-state responsibility.

The reqwest URL is constructed from one validated `HttpsEndpoint`; composition
verifies that its origin is unchanged. The transport's `EndpointIdentity`
comes from that same endpoint. Reqwest therefore derives Host and TLS SNI from
the destination already checked by prepared endpoint policy, not from caller
headers.

## Duplicate And Grammar Policy

Names accept the RFC HTTP token byte domain and are compared
case-insensitively without rewriting caller bytes. Request values are
canonical visible ASCII with no leading or trailing space. Response values
admit visible bytes and opaque bytes above ASCII while rejecting controls and
DEL.

Both identical and conflicting duplicates fail closed for request and retained
response metadata. This is intentionally stricter than general HTTP list-field
combination. Provider operations that later require repeated wire fields must
receive a dedicated typed representation and review rather than weakening this
default.

## Bounds

| Boundary | Limit |
| --- | --- |
| Header name | 64 bytes |
| One header value | 1,024 bytes |
| Request header count | 32 |
| Request encoded bytes | 8,192 |
| Retained response header count | 32 |
| Retained response encoded bytes | 8,192 |

Aggregate accounting includes `name`, `: `, value, and trailing CRLF for each
field line. It excludes the final empty line, framing generated by the HTTP
implementation, and response trailers.

## Compatibility

This is a pre-1.0 breaking release. `TransportRequest::with_content_type` and
`content_type` are removed in favor of `with_headers` and `headers`.
Testkit replaces content-type-only expectation matching with complete header
matching. Reqwest adds `TransportError::InvalidResponseHeaders`.
The new header and response types intentionally omit `Eq` and `PartialEq`;
testkit matching is an internal test-only operation.

See [`MIGRATION_0.36.0.md`](MIGRATION_0.36.0.md).

## Deferred Work

v0.37-v0.40 add sealed response-buffer provenance, cleanup-owning retained
metadata, immutable two-pass snapshots, and raw executor wire limits. v0.36
does not claim trailer support, complete process-allocation cleanup, or a raw
HTTP parser.
