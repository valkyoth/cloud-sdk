| secret buffer failure | path, query, header, and JSON writes preflight capacity and leave undersized buffers unchanged |
| secret buffer cleanup | `cloud-sdk-sanitization::SecretBuffer` volatile-clears the full caller-owned destination on drop; alloc-backed `SecretString` consumes owned UTF-8 without another plaintext copy, clears full allocation capacity on drop, wipes before growth, and permits only closure-scoped UTF-8 access |
| request preparation cleanup | `PreparationStorageGuard` ties prepared-request lifetime to one non-`Copy` owner, clears complete target and body storage before every preparation attempt and again on drop, including tails; profile validation establishes cleanup ownership before either capacity can fail; embedded/default/large profiles are bounded and owned allocation is explicit and fallible |
| response workspace cleanup | core mandates the single admitted volatile primitive for complete caller-owned body and header storage, temporary content type, request identifiers, cursor/provider-link staging, decoder scratch, and lifecycle scalars; sensitive header bytes remain at a stable address while movable state contains only non-secret locators; additive platform hooks run between mandatory body clears and cannot replace the final clear |
| retained response metadata | request-ID policy is explicit per operation (`Retain`, `Protected`, or `Discard`); retained state wraps stable caller-owned destination storage, is non-`Copy` and closure-accessed, and copies directly from stable header storage with source cleanup on success or failure |
| private-key output | escaped atomic writer only; no raw accessor or ordinary equality; guarded cleanup tested |
| DNS TSIG policy | HMAC-SHA256 only; canonical Base64; minimum 32 decoded bytes; no ordinary equality on secret-bearing types |
| DNS RRSet mutations | source-locked RR types; bounded unique redacted records; mandatory change-TTL intent; atomic JSON-string writers |
| optional Serde boundary | default graph exclusion; no Serde or serde_json `std`; 1 MiB request and 8 MiB response policies; direct duplicate-rejecting checked-response parser with a shared 65,536-node budget, bounded depth/containers/strings, and volatile-clearing decode storage for escaped and unescaped string values and object keys, including ignored extensions; protected provider/action error messages; source-locked checked decoding for every active operation; typed actions, resource identities, pagination, special results, and provider errors |
| testkit boundary | no_std ordered mock; atomic bounded response writes; payload-free mismatch errors; redacted fixture/request debug |
| transport contract | shared-reference blocking plus executor-neutral async traits; response mutation and commitment are private outside cleanup-owning attempts; attempts clear prior residue on entry and complete uncommitted body/header storage on error, unwind, timeout, or cancellation; prepared execution mandates complete response-storage sanitization before endpoint verification and capacity admission; normalized credential-free endpoint identity; exact Hetzner official-endpoint verifier derived from the canonical base-URL constants for both v1 API families; origin-form targets reject leading `//`, backslash, fragments, controls, spaces, and non-ASCII; responses borrow their initialized caller-buffer slice; core preserves absent versus malformed content type and rejects every present parse failure before provider decoding; no independent untrusted body length; no authentication, headers, TLS, retry, runtime, or network implementation |
| authentication policy | type-separated bearer and Basic credentials; mandatory provider/service/normalized-HTTPS-endpoint binding; exact `Required` base-identity policy plus provider or operation-owned `Required`, `Optional`, or `Forbidden` audience/account/tenant rules; configured endpoint mismatch, base-rule downgrade, omission, forbidden presence, and mismatch fail before credential snapshot or header construction; bearer refresh handoffs bind to one lineage and generation; Basic delimiters/charset/length are bounded; authenticated clients do not implement policy-free transport traits |
| canonical signing input | v2 bounded length framing over provider, service, normalized endpoint with tagged DNS/IPv4/IPv6 identity, optional scope, key ID, distinct digest and signature algorithms, exact method/target, selected headers, internally coupled exact-body digest, nonce, and time; equivalent IPv6 spellings encode identically; body hashers report and must match the signed digest algorithm; retains the exact request; validates signer output; digest, canonical, and signature storage clear on failure, unwind, or drop; cryptography, keys, clocks, randomness, replay, and verification remain caller/provider policy |
| optional blocking transport | cloneable shared non-default reqwest/rustls client; HTTPS only; TLS 1.2 minimum; HTTP/1 and system DNS forced under feature unification; explicit bounded timeouts and user agent; no redirect, retry, proxy, referer, decompression, queue, or background worker; exact response bounds; payload-free failures |
| optional blocking FIPS mode | dedicated non-default feature; exact published FIPS/TLS constraints; explicit rustls FIPS provider; provider and complete client configuration checked at runtime; mandatory deployment roots and complete CRLs; chain-wide unknown-status denial and CRL-expiration enforcement; FIPS path wins under additive blocking features; a fresh isolated generated crate archive must contain and compile its public verifier fixtures; bundled Cargo-authenticated native source in repository checks; no current module-certificate, application, deployment, or organizational compliance claim |
| optional async transport | cloneable shared non-default reqwest/rustls client with caller-provided Tokio execution; blocking feature excluded from async-only graph; no credential lock across `.await`; complete-success response copy from bounded sanitized temporary storage; cancellation, timeout, read failure, and overflow leave caller output cleared |
| quota and retry metadata | transports retain only bounded provider-admitted headers and reject duplicates; provider decoders reject malformed, partial, zero-limit, overflow, and incoherent buckets; core separates duration, wall-clock, and HTTP-date values and returns only pure caller-maximum-bound decisions with explicit stale, rollback, unknown-reset, and conflict policy |
| pagination state | distinct no_std numbered, offset, cursor, marker, and provider-link strategies; hard request/item/state/history budgets; exact bounded snapshot identities; transactional progression; cleanup-owning non-Copy opaque state; exact cursor history with cycle and digest-collision rejection; raw provider links retain endpoint/method/operation/exact-path identity, couple endpoint verification to blocking or async authenticated execution through the same transport object, flatten validation and transport failures into one result, redact transport-error diagnostics, and remain barred from structured recomposition; drift, contradiction, empty continuation, unbound transport, authority/scheme/userinfo/fragment/path/method/operation changes rejected |
| action polling state | no_std caller-driven poller; terminal provider failures take precedence over progress telemetry and are preserved; running progress regression and zero delay rejected; caller policy owns backoff, cancellation, timeout, sleep, and request execution |
| live smoke harness | ignored by default; repository-anchored clean-commit staging without credential variables; privileged installation into root-owned non-writable paths; isolated root-owned runtime validates ownership, modes, link count, bounded manifest, and open-descriptor SHA-256 before descriptor execution; authenticated phase invokes no Cargo/build tooling; exact read-only opt-in; fixed official origin; private regular token-file input; single-allocation bounded token read and guarded cleanup; Unix symlink, permission, and opened-file identity checks; typed GET-only catalog probes; static diagnostics without token paths, bodies, or IDs; destructive mode rejected |
| destructive live tests | not implemented; future plan requires a separate command, disposable project, short-lived read-write token, unique prefix, explicit pricing review, cleanup on every path, and empty post-run inventory |
